# 石家庄主配微潮流计算

基于提供的石家庄 13 点 / 20 点 DAT 计算交流潮流。按用户指定，当前计算默认将 T 卡 R/X 解释为 100 MVA 基准，再换算到文件的系统基准；L 卡使用文件系统基准。这个设置是建模假设，不代表已证实 BPA 存在固定 100 MVA 规则。原始文件字节不改，过载结果不截断。默认算法为加权分区＋并行 Newton–Schur，提供真实逐轮日志和回放。

当前结果、基准换算与原系统基准对照见 [T 卡 100 MVA 建模设置](doc/T卡100MVA建模设置.md)。旧报告的 489% 等结果属于原系统基准解释，不是当前默认工况。

## 启动

当前已验证的 Python 版本为 3.11：

```bash
python -m pip install -r requirements.txt
python start_api.py
```

本机现有环境可直接运行：

```bash
/home/y/miniconda3/envs/powerflow/bin/python start_api.py
```

打开 <http://127.0.0.1:4173/>。同一个服务同时提供网页、计算接口与实时事件流，不需要额外启动静态 HTTP 服务。

页面打开和刷新均为空白待上传状态，不自动选择石家庄断面、不加载历史结果。必须点击“选择数据文件夹”，上传原始 DAT 后才能运行；一个上传文件夹作为一套数据集，多个 DAT 作为其中的运行断面，通过“计算时刻”按钮选择。完成后拓扑、节点详情、分析表格更新为本次现场计算结果。接口失败、求解未收敛、分区未通过分别报告。

## 当前数据范围

当前应用只提供原始数据上传与计算，不再提供复制扩展的万节点／十万节点入口；带有复制扩展标记的 DAT 上传会被拒绝。请在网页中选择 `raw_dataset/extracted/` 文件夹，识别 13 点（2,121 母线）和 20 点（2,122 母线）原始断面及配套表格。

`data/synthetic/` 及相关说明仅保留为历史构造实验，未作为真实十万节点电网验证。旧合成基准结果不能代表真实大电网性能，也不能证明连接与控制假设符合实际。

## 输入与计算含义

- 唯一原始输入目录：`raw_dataset/extracted/`，保留 2 个 DAT 和 19 个配套 XLS；校验值见 `doc/repository_cleanup.json`。
- 全部算法采用相同的 T 卡 100 MVA 基准假设：`R/X_system = R/X_input × system_base / 100`。L 卡不乘该倍率。系统基准、P/Q、BE/BS 控制、固定分接值、拓扑及设备额定值保持输入值；BE 仍按恒 P/V 求解。结果记录原始 R/X、换算后的 R/X、倍率与建模假设。
- 支持配网分区并行牛顿、普通牛顿、阻尼牛顿、解耦启动加牛顿。最后一种参考公开 BPA/IPF 流程，不是 PSD-BPA 软件，也不声称复制其闭源内核；来源与范围见 `doc/tools/bpa_style_solver.md`。
- 原始零阻抗 L 卡精确合并，计算后按 KCL 恢复支路潮流；全部 91 条变压器 T 卡均展示。
- 配网节点按低于 35 kV 的模型基准划分。METIS 按串联导纳设置边权、按交流未知量及连接度估计点权，并检查分区连通性；在 64／128／256 三种目标粒度中按结构成本估计选型。分区数量随阻抗基准解释、模型和候选选择变化，以本次日志为准。原始主网及跨区支路的两端均保留在 Schur 协调器，各区内部由 Numba 原生 CPU 线程并行消元及回代。详见 [分区算法与基准](doc/配网分区并行求解与基准.md)。
- 普通牛顿直接解全网，不再强制追加数千次局部校核。旧固定边界验证仍可通过 Python 的 `run_case(..., algorithm='nr', partitioned=True)` 显式执行，其耗时不能用于声称分区算法胜过纯牛顿。
- 原断面的 6 个微网 PCC 标记为研究假设接入点，未确认其实际微网身份。当前不计算微网内部网架，也不增加微网注入。
- “各10kV馈线”的 18 份详细馈线表及 1 份分类目录属于同一数据集。上传时按原字节保存，当前未解析接入潮流模型，也不覆盖 DAT 断面负荷；与合并 DAT 的节点及接入关系尚待核对。页面、日志与运行记录明确标注该输入范围。
- 拓扑坐标仅用于电气工程图，不代表实地线路走向。没有对坐标缺失编造地理数据。

## 文件夹导入

点击“选择数据文件夹”，选择含 DAT 的文件夹。页面显示一套数据集的名称、DAT／馈线表／目录组成和完整文件清单；同一数据集内通过“计算时刻”按钮选择 13:00／20:00 等运行断面，不使用数据集下拉框。多个断面时必须手动选择一个，只有唯一断面时自动选中；未标注时刻的 DAT 按文件名显示，不编造时间。母线与支路数属于所选断面，切换时刻会清空上次计算结果。支持 B、BE、BS、L、固定分接 T 卡，不支持的控制卡会报错。上传文件按原字节保存到 `runtime/uploads/`，不会覆盖原始数据。

上传、时刻、算法和运行按钮集中在顶部，拓扑使用剩余屏幕空间；文件清单及输入范围收进“数据集详情”。桌面无需上下滚动即可同时看到运行按钮和拓扑，小屏幕保留置顶运行栏。

点击节点会显示计算分区、内部／边界角色、相邻分区；拓扑高亮整个分区和边界。展开右侧“边界迭代明细”可查看线程、局部耗时、逐轮残差与接口两侧 P/Q。电流动画沿当前图层中全部可见、有电流的线路及变压器绘制，不抽样；方向依据 P（纯无功时依据 Q），零电流支路保持静止，速度仅为展示示意。计算结束即停止自动动画，可手动开启最终结果电流示意。“迭代记录”默认收起，仅在用户点击后回放，支持暂停、逐轮、速度控制和返回最终结果；不延长或改写求解用时。迭代中节点 P/Q 明确标为理想连接合并母线组净注入，最终结果恢复到原始节点。

## 目录

```text
gmss/                  DAT 解析、求解、分区、展示数据、任务与 HTTP 服务
raw_dataset/extracted/ 石家庄唯一原始 DAT / XLS
data/demo_area/         电气图布局坐标
data/synthetic/         历史复制实验归档，不作为网页计算入口
web_sjz/               HTML / CSS / JS、历史离线快照工具
tools/                 命令行结果导出
tests/                 解析、算法、物理一致性及接口回归测试
doc/                   原 Word / PDF / WPS、报告附件、清理记录
runtime/               新计算结果、日志、上传数据（不纳入 Git）
```

历史快照生成工具 `web_sjz/build_data.py` 仅用于离线检查；网页启动不再读取 `data.js`。

导出原始断面的 CSV / JSON：

```bash
python tools/run_raw_dat_powerflow.py --algorithm nr
```

默认按进程 CPU 亲和性识别可用逻辑 CPU，本机 24 个，无固定 8 线程封顶。可以设置 `GMSS_WORKERS=4` 限制并发，`GMSS_PARTITION_TARGET=128` 固定候选粒度。分区数量与线程数量独立，结构成本估计不等于已证明全局最优。首次安装后 Numba 编译会额外耗时，编译缓存不是潮流结果缓存。

符号消元采用原生内核，并对已经分离的内部子图统一排序，减少逐区 Python／SciPy 操作。进程内有界缓存只保存分区及消元结构索引：分区复用核对连接、节点类型、电气权重及候选配置，消元复用核对实际稀疏模式与分区归属；每次均重新读 DAT、组装数值矩阵并从平坦 PQ 初值求解。日志和运行记录分别显示首次构造／结构复用、准备及迭代耗时。原始数据性能验收见[性能核查报告](doc/原始数据分区性能核查.md)。

原始断面性能对比：`python tools/benchmark_partitioned.py --pipeline page --repeats 30 --uncached-repeats 10`。默认读取原始数据，不再使用合成十万节点；报告分别保存进程首次请求、重复运行和清空结构缓存后的对照。`--pipeline raw` 单独测量无界面遥测的求解流程。

HTTP 并发压测：服务启动后运行 `python tools/stress_http.py --jobs 4 --subscribers 2`。脚本先上传原始数据文件夹（可用 `--folder` 指定），在 13 点／20 点断面之间交替提交。多个任务排队执行，每个任务内部使用多核，避免多个满核任务互相争用；验证每个 SSE 订阅者的事件完整性、全网 KCL、分区残差、结果与输入身份。该压测与无界面数值基准分开进行。

运行测试：`python -m unittest discover -s tests -v`。

## 接口

- `GET /api/datasets`：已上传的数据集列表（每套含 `snapshots` 运行断面）、可用算法；没有内置预设，网页不会自动选择历史上传。
- `POST /api/datasets/import`：上传一个目录的文件，内容为原字节的 Base64；返回 `{"dataset": {...}}`，不是逐 DAT 返回多套数据集。旧的逐 DAT 注册记录会按原上传文件夹自动归组，不移动或修改原文件。
- `POST /api/runs`：`{"dataset_id":"upload-数据集ID","snapshot_id":"snapshot-断面ID","algorithm":"partitioned-nr"}`，返回任务 ID；数据集与其断面 ID 均必填，不能跨数据集选择。省略算法时使用分区并行算法。
- `GET /api/runs/{id}/events`：SSE 实时日志、迭代电压、分区进度与结束状态。
- `GET /api/runs/{id}/result`：本次完整结果及耗时、残差、源文件哈希。
- `GET /api/runs/{id}/trace`：下载完整结构化事件，含逐区指标、边界 P/Q、节点迭代状态及真实阶段顺序；大模型状态采用无损 Float64 Base64 编码。

每个任务在 `runtime/runs/{id}/` 保存结果和事件日志。过载不会被当作数值不收敛，成功也不会被解释为所有设备都满足限额。

无关算例、旧缓存、PPT、ZIP、图片及无用脚本已移入系统回收站，未永久删除。逐项原路径、回收站路径与资料迁移位置见 `doc/repository_cleanup.json`。`.git` 与原有 IDE / 工作区配置保留。

历史报告原文归档到 `doc/`，当时的结果与性能数据对应各自记录的模型设置。当前规则以本文件及《T 卡 100 MVA 建模设置》为准，不把历史 489% 与当前换算工况混用。
