# T 卡 100 MVA 建模设置

生效日期：2026-10-19。用户指定当前项目将 T 卡阻抗固定按 100 MVA 解释。
这是明确选择的建模假设，尚未证明原数据 T 卡确实以此基准填写，也不代表
PSD-BPA 通用规则。未执行 PSD-BPA 软件对照，不能称为已确认的解析器修复。

## 换算范围

- 系统基准保留 DAT 中的 1000 MVA，L 卡 R/X 按此基准使用。
- T 卡 R/X 输入按 100 MVA 解释，乘 `1000 / 100 = 10` 换算到系统基准。
- 只转换 T 卡 R/X。原始文件字节、L 卡、负荷、额定容量、固定分接及 BE/BS
  控制不变。非零 T 卡励磁字段仍明确拒绝，未猜测其基准或等值方式。
- 普通牛顿、阻尼牛顿、解耦启动＋牛顿、并行 Newton–Schur 使用相同模型。
- 结果、日志及 CSV 记录假设、系统基准、原始阻抗、换算倍率及实际求解阻抗。
  电流负载率与视在功率容量比分开保存，不以限幅改变结果。

## 原始两个断面的对照

I 为两侧计算电流／额定电流的较大值，S 为两侧视在功率／额定容量的较大值。
全部 91 条 T 支路均计入，包含三绕组星形等值支路，不等于 91 台独立实物设备。

| 指标 | 13 点原系统基准解释 | 13 点 T=100 MVA | 20 点原系统基准解释 | 20 点 T=100 MVA |
| --- | ---: | ---: | ---: | ---: |
| GXVS2→GXVY2，I% | 397.895716 | 74.894686 | 489.259635 | 83.579829 |
| 全部 T 最高 I% | 654.875762 | 206.360826 | 829.382588 | 288.723053 |
| 全部 T 最高 S% | 657.366525 | 199.334340 | 817.439499 | 273.626374 |
| 线路最高 I% | 366.367194 | 359.642261 | 553.203773 | 533.151521 |

因此不能称“两份断面全部降到 200%”。199.33% 仅是 13 点的 T 支路最高 S
口径；20 点最高 T 支路电流负载率仍约 289%，线路也仍有严重越限。

## 复现与原模型对照

项目 API／网页及 `raw_solver.solve()` 默认 T=100 MVA。底层 `read_dat()` 默认
仅按文件系统基准解析，必须传入 `transformer_base_mva=100.0` 才执行转换。
这样可以独立检查原始数据和使用标准系统基准的其他算例。

```bash
# 当前默认：T 卡 100 MVA 假设，结果输出到独立目录
python tools/run_raw_dat_powerflow.py --transformer-base 100 --output-dir runtime/exports/t100

# 原系统基准解释，保留原回归结果作为独立对照
python tools/run_raw_dat_powerflow.py --transformer-base system --output-dir runtime/exports/system
```

Python 对照：`solve(path, transformer_base_mva=None)`；页面编排也支持
`run_case(path, transformer_base_mva=None)`，不改变默认的 T=100 MVA 设置。

历史报告和性能记录未改写，其结果应按原文的建模设置解读；新工况需要重新
测量性能，不将旧基准速度或原先 489% 的电流直接套用到当前模型。

## 本次验证

- 32 项相关检查通过：100／1000 MVA 系统基准下同一物理变压器电压一致；
  仅 T 卡转换、L 卡及其他参数不变；原 21 个文件 SHA-256 保持清理清单值；
  四种算法、原模型对照、原节点 KCL、分区协调与 HTTP/SSE 均通过。
- 实际浏览器上传完整文件夹，对两个断面分别运行普通牛顿与并行
  Newton–Schur，验证目标值、最高 I% 分表、假设标注、完整 CSV 导出和
  刷新后清空。1366×768 下运行按钮与拓扑同屏，未出现 JavaScript 错误。
- 结果导出：`runtime/exports/t100/results.json`，原模型对照：
  `runtime/exports/system/results.json`；浏览器验证记录：
  `runtime/benchmarks/t100_browser_validation.json`。
